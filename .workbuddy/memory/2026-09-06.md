## Scrum Master Agent 项目搭建

从零搭出 `scrumMasterAgent` 骨架，目标：把每日 DSU 会议 → 结构化 JSON → 每 pod 一份静态 HTML，托管在 GitHub Pages。

关键决策：
- GitHub 仓库同时当数据库 + 托管平台，不引入额外 DB/对象存储。`pods/<pod>/dsu/<date>.html` + `raw/<date>.json`，`data/dsu-index.json` 供前端检索。
- 后端 Python(FastAPI)，流水线四步：ingest → extract(LLM) → enrich(Jira/GitHub MCP) → render(Jinja2) → publish(GitHub MCP push_files 批量提交)。
- MCP 用 `mcp` Python SDK 的 stdio 客户端，配置沿用标准 `mcpServers` JSON（与 `~/.workbuddy/mcp.json` 同构），`${VAR}` 从环境变量展开。
- 发布默认走人工确认闸门（`REQUIRE_HUMAN_APPROVAL`），草稿先进 `.workdir`，确认后才 commit。Jira 写操作默认关闭。
- mcp 依赖在 enrich/publish 里延迟导入，保证没装 mcp 时本地渲染链路仍可跑。

## 角色视图设计（用户问 Scrum Master 报告该给不同人看什么）

数据源统一（每 pod 一份 raw JSON），按 persona 在视图层切：

- SM 自己：trend + 老化阻塞 + 行动项闭环 + 沉默/过载成员
- 工程师：自己那条 + 自己负责的 Jira/PR + 自己被 owner 的行动项
- EM / Lead：health_score 趋势 + Sprint 进度 + scope_changes + 跨 pod 阻塞（看根 index 聚合）
- PO：delivery + 范围变更 + 阻塞 + Jira 状态 + 决策
- VP / 总监：周/月聚合 — health / 阻塞 / 缺陷 / 部署趋势，不看每行
- 跨团队协作者：blockers_m.cross_team / external + 对方 owner 的行动项
- HR / People Ops：silent 趋势、overloaded 趋势、出席率（burnout 早期信号）
- 新人 onboarding：历史决策 + Jira/PR 表 + scope 变更史
- 客户 / 干系人：health + 阻塞摘要 + ETA，剥掉内部细节

实现分 4 类：(1) 单 pod 角色视图 me/manager/po/cross-team.html，模板用 data-persona 标签按 query 过滤；
(2) leadership.html 跨 pod 总览；(3) weekly/monthly 聚合任务读 raw JSON 派生；
(4) pods/<pod>/index.html 扩展为时间线 + 决策 + Jira 表。

优先级：先做 SM 自己的趋势视图（他是唯一会主动看的人），其余角色做得越短越好。

`backend/verify.sh` 留作冒烟脚本，团队成员 clone 后跑一次即确认依赖与产物正常。

## 第六轮：Scrum Master 产品调研对比报告

调研 Spinach AI / Geekbot / Standuply / Range / DailyBot / Status Hero（站会助手）、LinearB / Swarmia / Waydev（效能平台）、Jellyfish / Pluralsight Flow（高管智能）等 12 款产品，产出 `docs/scrum-master-products-comparison.md`（已提交 fca5b88）。

核心结论：
- 赛道三分：A 会议/站会助手（记录型）、B 效能平台（DORA/周期/健康）、C 高管智能（投资分配/资本化）。无人同时覆盖「站会级 + 高管级」粒度。
- 本项目差异点：站会级诊断 + 六维健康雷达 + 情绪/会议质量/反复主题 + 一份 raw JSON 派生多角色视图，正好填补 A/B/C 之间的缺口。
- 借鉴清单（按优先级）：P1 分角色摘要 + 站会前阻塞预警；P2 DORA 四指标 + 投资分配 + 速率时间序列（并入路线 P5）；P3 DX 调研 + working agreements；P4 站会计时/发言顺序。
- 独家维度：`meeting`（会议质量）市面无同类；情绪从语气识别（非自报）也领先。

## 第七轮：建设策略文档

基于调研产出 `docs/scrum-master-agent-strategy.md`（已提交并 push b07349e），回答「该怎么做出差异化」：
- 定位：站会级 AI 诊断 + 多角色派生（对标 Spinach 向左、Swarmia 向右、Jellyfish 向上，不碰财务/资本化）。
- 一句话记忆「别人记录会议，我们诊断团队」。
- 报告维度分三层：记录层 / 诊断层（health/meeting/sentiment/recurring_themes 等护城河）/ 预测教练层；待补 DORA(接 CI/CD)、投资分配、DX 调研。
- 路线图 P0-P5 修订：把竞品借鉴点（分角色摘要 P1、站会前风险清单 P1、DORA P2、DX 调研 P3、站会计时 P4）显式塞进阶段。
- 北极星：每周被 SM 主动打开并据以行动的诊断报告数；人机边界=AI 替行政、不替教练。
